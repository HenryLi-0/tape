anyways, today in the shower, i dreamnt up some idea for how to do the node thing, and i think its pretty/relatively intuitive? basically we're aiming for a node based editor for basically everything. no sprites list tab or property tabs, but a single node grid editor for everything (and i guess maybe an export panel but thats for the future)

since i have no clue what words to use, i'm gonna use "node" to describe the block thingies that connect with eachother!

so this idea should make a pretty flexible and allow users to create pretty cool looking wire things, while also still allowing for precise number stuffs that Tape v1 didn't really support easily

Node Types:
- Numbers: A single value and just a value, no units or anything
  - In: nothing
  - Out: a number
- Unit: gives numbers units
  - In: a number, or a number with a unit
  - Node: a group (ex. time), and unit (ex. minutes)
  - Out: a number with the unit
  - Ex: In: Seconds(60), Node: Time>Minutes, Out: Minutes(1)
- Operations: does math, addition and multiplication (for now)
  - In: 
- Path: a path of values over time t with given path creator, but not necessarily for an exact time, more like x at time t, and y at time t+5
  - In:
- Motion: Unit(Number) + Path -> A path but with time!
  - In: Time(Number) (starting time) and Path
  - Out: a motion
- Motion Merger: merges motions for more advanced stuff with timing and things, for example, merging a straight glide from t=0 to t=1 and a smooth glide from t=1 to t=2, if overlap detected, show a warning but prioritize the first processed
  - In: any number of motions
  - Out: a motion


we know have a funny graph of value over time, but what's that gonna feed into?
- Propertizer: weird name, idk what to call it, but turns a motion into a property, for example, Rotation(Motion), meaning a motion for rotation to follow with the given units!
  - In: a motion
  - Out: a propertized motion
- SPRITE: one of the ultimate endings, gets controlled by everything previously
  - In: many propertized motions
  - Out: none! just a sprite on the screen!
- CAMERA: another ultimate ending, controls the camera properties, so if rotation is applied, everything gets rotated like if an actual camera recording it was rotated

future ideas that need to be cleaned up
- Image: sprites need apperances and stuff! current idea supports a still image, but what about multiple images over time?
  - Idea: an Instant Path, takes in two images, can be added to a motion to create a sequence of time for a sprite over time
- Randomizer: adds random noise to stuff, has a min and max parameter, can be added in with an Operation
- relativity stuff: one of the ideas of the new system was staying relative to another location, say another sprite, idea is currently to have sprites also output Unit(Number) to be fed into other systems
- If or Switch: switch between two things if something satisfies or doesnt satisfy a condition, might be confusing/hard for users and to add, but could be REALLY useful
- timing controls: change FPS or speed?
- Redirect: a simple grey box that takes in anything and outputs it, just for organizing purposes
