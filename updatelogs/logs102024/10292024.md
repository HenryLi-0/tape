- More Advanced Position
  - Previous Position Limited by:
    - Mouse/Graph Accuracy (Cursed keybind position editing)
    - Tedious (If two objects needed to be synced up, it was ridicously hard)
  - New Features:
    - (obviously) Exact control over position
    - Relative/Linked Sprite Positioning (Stay a relative distance away from another sprite's position + offset)
      - Allows for sprites to easily be linked with other things
- More Advanced Rotation
  - Previous Rotation Limited by:
    - Graph Accuracy (previous)
    - Tedious (It was always focused around the center of the sprite, making users need to involve positions when rotating around a point that's not the sprite's center)
  - New Features:
    - (obviously) Exact control over position
    - Offset Rotation Center
      - Allows for limb-like movement
    - Relative/Linked Sprite Rotating (Rotates with another sprite)

basically, the graph based editor was probably not my brightest move when it came to thinking of an editor. instead, im thinking of going into a more numbers with graphics based approach. so, with more of a UI, it should allow for space on the UI to "link" properties with other sprites. for example, we can have transparency equal across multiple sprites with linked properties, and have an offset modifier, incase someone wants extra fine tuning

of course, we need to implement ranges so that we dont go into cursed parameters territory, but having a more numeric editor would fix a lot of old issues such as precision. one thing that still kind of haunts me today is how resizing was done. since our graph in Tape v1.x was limited by height, we had some very cursed code, i'll let you read it. (this was taken from `render.py`)

```python
def setSize(img: numpy.ndarray, size):
    '''Returns a copy of the given image scaled by size, given the size change (given with 50 as normal, >50 scale up, <50 scale down)'''
    '''EDITING WARNING: IF CHANGED, MUST UPDATE THE REGION LOGIC.'''
    y, x = img.shape[:2]
    return numpy.array(Image.fromarray(img).resize((max(1, (round(x*(size/50)**2))),max(1, round(y*(size/50)**2)))))
```

so the minimum size was 1x1 pixels, but the maximum size was a scale of x4, since we are limited by the 0-100 range of the graph. basically, very weird problem, new idea can fix it!
